Revit Design Automation

Guía APS Design Automation

Documento de referencia para entender, en lenguaje claro y en detalle técnico, cómo se publica el add-in de Revit en APS y cómo el backend de eduardoos.com lo ejecuta.

Resumen ejecutivo (para cliente)

¿Qué hace esto? Permite procesar un archivo de Revit (.rvt) en la nube de Autodesk, sin abrir Revit en una PC local, y obtener un JSON con datos del modelo (muros, puertas, ventanas, etc.).

Parte 1 — Publicar el add-in en APS Es como “instalar” nuestro mini-programa de Revit en los servidores de Autodesk. Lo hacemos una vez por versión de Revit (hoy: Revit 2027). Cuando cambiamos el código, volvemos a empaquetarlo y subirlo.

Parte 2 — Ejecutar desde eduardoos.com El usuario autorizado entra a /aps-admin, pulsa un botón, y el sitio:

  1. Pide permiso temporal para leer el .rvt y escribir el resultado en nuestro almacén (S3).
  2. Encola un “trabajo” (WorkItem) en Autodesk.
  3. Autodesk abre el modelo con Revit en la nube, corre nuestro add-in y guarda result.json.
  4. La web consulta el estado hasta que termina y muestra el JSON.

Coste y tiempo: Autodesk cobra por tiempo de procesamiento en la nube (tokens Flex). Un modelo pequeño puede tardar ~30–60 segundos. Fallos típicos: versión de Revit del .rvt distinta a la del motor en la nube, o permisos de S3.

Seguridad: Solo el correo admin (eduardooost@gmail.com) puede disparar trabajos. Las credenciales de Autodesk y AWS no van al navegador; viven en el servidor.

Parte 1 — Cómo subir un add-in a APS (paso a paso)

Conceptos en una frase

AppBundle El ZIP con el add-in (RevitHello.dll, manifiestos, etc.).
Activity La “receta”: motor Revit + AppBundle + argumentos (entrada RVT, salida JSON).
Alias (dev) Apunta siempre a la última versión publicada del bundle/activity.
Engine Versión de Revit en la nube, p. ej. Autodesk.Revit+2027.

Paso a paso (operación)

  1. Escribir el add-in C# en aps_app/RevitHello/. Hoy extrae IDs de muros, pisos, puertas, ventanas, techos, habitaciones y metadatos del archivo.
  2. Compilar contra la API de la misma versión de Revit que usará APS: 
    cd aps_app/RevitHello
dotnet build
    Revit 2027 usa net10.0-windows y paquetes NuGet 2027.
  3. Empaquetar el bundle (estructura que exige Autodesk): 
    powershell -ExecutionPolicy Bypass -File aps_app/pack-bundle.ps1
    Debe quedar un ZIP con carpeta raíz RevitHello.bundle/, no solo Contents/ sueltos.
  4. Configurar credenciales en .env (no se suben a git): APS_CLIENT_ID, APS_CLIENT_SECRET, y opcionalmente APS_ENGINE=Autodesk.Revit+2027.
  5. Registrar en APS (sube bundle + crea/actualiza activity): 
    node aps_app/register-revit-activity.mjs
    El script:
    • Obtiene token OAuth de Autodesk.
    • Crea nueva versión del AppBundle y sube RevitHello.zip.
    • Actualiza el alias dev.
    • Crea nueva versión de la Activity con el engine correcto.
    • Guarda APS_ACTIVITY_ID en .env.
  6. Copiar IDs al servidor / CI: APS_ACTIVITY_ID, APS_CLIENT_ID, APS_CLIENT_SECRET en GitHub Secrets y en el .env de producción.
  7. Subir el modelo de prueba a S3, p. ej. s3://aps20250806/singleRoom.rvt. La versión del RVT debe ser ≤ la del engine (2027 abre RVT 2027, no al revés).
Multi-versión: si necesitas procesar RVT de 2025, 2026 y 2027, publica un AppBundle + Activity por año, cada uno con su DLL compilada para esa versión. No mezcles varios años en un solo bundle.

Parte 2 — Cómo el backend ejecuta APS

Flujo en lenguaje simple

La página /aps-admin no habla directo con Autodesk. Llama a nuestro API gateway (Go), que es quien tiene las claves, firma URLs de S3 y crea el WorkItem.

Usuario (JWT) → /aps-admin (React) │ ├─ POST /api/aps/trigger-workitem ──► Gateway Go │ • valida email admin │ • pre-firma GET singleRoom.rvt (S3) │ • pre-firma PUT result.json (S3) │ • POST WorkItem a APS │ ◄ devuelve workItemId (202 Accepted) │ └─ cada 4 s: GET /api/aps/workitems/{id}?outputObjectKey=... • consulta estado en APS • si success → lee result.json de S3 ◄ devuelve extractedData (JSON)

Endpoints del gateway (este repo)

MétodoRutaQué hace
POST /api/aps/trigger-workitem Encola el trabajo. Respuesta rápida con workItemId y outputObjectKey.
GET /api/aps/workitems/{id} Consulta APS. Si terminó bien, devuelve el JSON extraído desde S3.

Detalle técnico — submit (trigger-workitem)

  1. Middleware: JWT → email debe ser eduardooost@gmail.com.
  2. aps.NewPresigner — URLs firmadas AWS para bucket aps20250806:
    • GET singleRoom.rvt (input)
    • PUT aps-outputs/{uuid}/result.json (output)
  3. aps.NewClient — OAuth client_credentials contra Autodesk.
  4. CreateWorkItem — body ejemplo: 
    {
  "activityId": "…RevitHelloActivity+dev",
  "arguments": {
    "inputFile":  { "url": "https://aps20250806.s3…", "verb": "get" },
    "outputFile": { "url": "https://aps20250806.s3…", "verb": "put" }
  }
}
  5. Respuesta HTTP 202 Accepted (no espera a que Revit termine; evita timeout de nginx).

Detalle técnico — poll (workitems/{id})

  1. GetWorkItemStatus → GET …/da/us-east/v3/workitems/{id}
  2. Si status es pending / inprogress → done: false
  3. Si success → GetObjectJSON del outputObjectKey en S3
  4. Si falla (failedInstructions, etc.) → incluye reportUrl / texto del report en debug_logs

Qué corre dentro de Revit en la nube

  1. APS descarga input.rvt con la URL firmada.
  2. Revit Core Console abre el modelo con el engine configurado (2027).
  3. Se carga RevitHello.dll del AppBundle.
  4. El add-in ejecuta ExtractDocumentData → escribe result.json.
  5. APS sube result.json a S3 con la URL PUT firmada.
